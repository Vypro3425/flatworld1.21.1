# Flat World Portal (flatworld)

Мод для **NeoForge 1.21.1**. Добавляет блок **Спрессованный камень** (`flatworld:compressed_stone`),
из которого можно сложить рамку наподобие незер-портала. Подожжённая обычным кремнём и сталью
рамка открывает **зелёный портал** в собственное измерение — мирный супер-плоский мир.

## Что реализовано

- **Спрессованный камень** — крафтится из 9 булыжника (сетка 3×3, как блок из блоков).
- **Портал** (`flatworld:flat_portal`) — зажигается ванильным Flint and Steel в рамке из
  Спрессованного камня (минимум 2×3 внутренних блока, максимум 21×21, как у незер-портала).
- **Измерение `flatworld:flat_world`**:
  - Супер-плоский мир: 1 слой бедрока, 10 слоёв камня, 3 слоя земли, 1 слой травы.
  - Мобы **не спавнятся самостоятельно** (естественный спавн полностью отключён кодом; можно
    призывать через `/summon` или яйца призыва).
  - **День длится 30 минут, ночь — 10 минут** (кастомный цикл, реализованный вручную,
    так как ванильный `dimension_type` не поддерживает настройку длины дня/ночи).
- **Обратный портал** создаётся автоматически на другой стороне при первом прибытии — как
  ванильный незер-портал (сначала ищется портал поблизости, если не найден — строится новый).

## Сборка — самый простой способ (без установки чего-либо)

В проект уже добавлен **Gradle Wrapper** (`gradlew`, `gradlew.bat`, `gradle/wrapper/...`) и
готовый workflow **GitHub Actions** (`.github/workflows/build.yml`), который сам скачивает
JDK 21, NeoForge и всё остальное, и собирает jar в облаке — вам не нужно ничего ставить локально.

1. Зайдите на https://github.com, создайте новый **пустой** репозиторий (публичный или приватный).
2. Загрузите в него содержимое этой папки одним из способов:
   - **Без командной строки**: на странице репозитория нажмите "Add file → Upload files" и
     перетащите туда всё содержимое папки `flatworld` (включая скрытые файлы `.github` и
     `.gitignore` — если веб-интерфейс их не подхватит при перетаскивании папками, можно
     загрузить архивом через "uploading via git" ниже).
   - **Через git** (надёжнее, сохраняет скрытые папки):
     ```
     cd flatworld
     git init
     git add -A
     git commit -m "initial commit"
     git branch -M main
     git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
     git push -u origin main
     ```
3. Откройте вкладку **Actions** в репозитории на GitHub — сборка запустится автоматически
   при пуше. Дождитесь зелёной галочки (первая сборка занимает 3-6 минут).
4. Зайдите в завершённый workflow-run → внизу раздел **Artifacts** → скачайте
   `flatworld-mod-jar` — это zip-архив с готовым `flatworld-1.0.0.jar` внутри.
5. Готовый `.jar` кладётся в папку `mods` вашего NeoForge 1.21.1.

Это бесплатно (GitHub Actions даёт бесплатные минуты сборки даже для приватных репозиториев)
и не требует установки JDK/Gradle/IDE на вашем компьютере — вся сборка происходит на серверах
GitHub.

## Сборка локально (альтернатива)

Если предпочитаете собрать на своей машине:


Проект нужно собирать на машине с доступом к `maven.neoforged.net` и серверам Mojang
(песочница, в которой этот код был написан, такого доступа не имеет, поэтому реальная
сборка `./gradlew build` не выполнялась — см. раздел «Известные риски» ниже).

1. Установите JDK 21.
2. В корне проекта выполните:
   ```
   ./gradlew build
   ```
   (на Windows — `gradlew.bat build`)
3. Готовый jar появится в `build/libs/flatworld-1.0.0.jar`.
4. Для запуска клиента в dev-окружении: `./gradlew runClient`.

## Как играть

1. Скрафтите Спрессованный камень (9 булыжника → 1 блок, крафт 3×3).
2. Постройте рамку минимум 4×5 (как у незер-портала: 2 блока внутренней ширины, 3 блока
   внутренней высоты, обрамлённые Спрессованным камнем).
3. Подожгите внутреннее пространство рамки обычным кремнём и сталью.
4. Войдите в зелёный портал — телепортирует в супер-плоское измерение.
5. Чтобы вернуться — войдите в портал, который автоматически появится рядом с точкой прибытия.

## Известные риски / что стоит проверить при первой сборке

Код написан с опорой на документацию и javadoc NeoForge 1.21.1 (без возможности реальной
компиляции в этой среде), поэтому при первом `./gradlew build` возможны точечные ошибки
компиляции. Наиболее вероятные места:

1. **`DimensionTransition`** (`PortalTeleportHelper.teleport`) — конструктор
   `DimensionTransition(ServerLevel, Vec3, Vec3, float, float, Consumer<Entity>)` с
   `DimensionTransition.DO_NOTHING` использован по памяти о стандартном паттерне 1.21.x;
   если сигнатура отличается, IDE подскажет правильный набор параметров (объект хранит:
   целевой уровень, позицию, вектор скорости, yaw, pitch и пост-коллбэк).
2. **`MobSpawnEvent.PositionCheck` / `FinalizeSpawnEvent`** — использованы актуальные на
   момент написания сигнатуры (`event.getLevel().getLevel().dimension()`,
   `event.getSpawnType()`, `FinalizeSpawnEvent.setSpawnCancelled(boolean)`).
3. **`LevelTickEvent.Post`** — использован для тика измерения; если у вас другая версия
   NeoForge, имя события/пакет могли измениться (`net.neoforged.neoforge.event.tick`).
4. Текстуры — простые процедурные заглушки 16×16, сгенерированные программно. Замените
   `assets/flatworld/textures/block/compressed_stone.png` и `flat_portal.png` на свои,
   когда будут готовы полноценные текстуры.

Если что-то из этого не скомпилируется — сообщение об ошибке компилятора укажет точную
несовпадающую сигнатуру, и я поправлю (пришлите текст ошибки).
